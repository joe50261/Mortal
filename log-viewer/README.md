# Log Viewer for mjai

This component is copied and modified from the artifacts generated by [gimite/mjai](https://github.com/gimite/mjai).

`index.example.html` is a ready-made example: an mjai game log baked into the
viewer. Open it in a browser to replay the game on a board (mouse wheel or the
*Prev*/*Next* buttons step through actions, *Viewpoint* rotates the seat).

## Recalculate a game and generate a page

[`mortal/review_to_html.py`](../mortal/review_to_html.py) re-evaluates every
decision point of an mjai game log with a trained Mortal model (recomputing the
Q values / `meta` for all four seats) and bakes the annotated log into a copy of
this viewer, producing a playable page.

Prerequisites:

- the `libriichi` extension module is importable (build it, see the docs);
- `torch` is installed;
- a Mortal checkpoint (`.pth`). The bundled placeholder is fine for a smoke
  test; community-trained weights produce meaningful analysis.

```sh
cd mortal

# write log-viewer/index.html (uses the files/ assets next to it)
python review_to_html.py \
    --model /path/to/mortal.pth \
    --input game.mjai.json \
    --output ../log-viewer/index.html

# or emit a single self-contained file (CSS, JS and tile images inlined),
# openable anywhere without the files/ directory
python review_to_html.py \
    --model /path/to/mortal.pth \
    --input game.mjai.json \
    --output review.html --standalone
```

Add `--analysis` to overlay a panel that, as you step through the game, shows
the recomputed Q values for every candidate of the player to act — each tile or
call with its Q value and softmax probability, marking the model's best move
(★) and the move actually played (◉), plus the shanten.

The input is an ordinary mjai log (one JSON event per line); any existing
`meta` fields are ignored and recomputed. `index.html` is git-ignored, so
regenerating it never dirties the working tree.
